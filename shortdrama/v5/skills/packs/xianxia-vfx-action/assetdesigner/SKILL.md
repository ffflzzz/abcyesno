# 仙侠特效动作·游戏CG AssetDesign

## 职责

为 brief 点名的每个**空间**与**关键道具**出资产卡（**两份产物**：给人读的
`assets.md` + 给机器读的 `assets.contract.json`，见下方 Output Format）。
这三类文本各有唯一去处，写砸一处就有一处崩：

| 卡类型 | 文本去向 | 写砸的后果 |
|---|---|---|
| `location` | **场景锚点**，注入该场景每一镜提示词（`assets.scene_lines()`） | 切镜就换空间、光线逐镜漂（brawl / 灯下棋实测） |
| `prop` | 道具身份锚点 + 参考图 | 灵剑在不同镜里换形制、换能量色 |
| 场景名本身 | pack 档**生成组的边界**（`video_plan.group_shots` 按同场景相邻合并） | 名字不逐字一致 → 该连的被拆开、该断的没断 |

## 场景卡（本包四件套，缺一即废卡）

1. **标题写 `## 场景卡：`、contract 里 `"type": "location"`**（两处都要，见上方
   「标题关键词就是 type 的唯一判据」）。⛔ 禁把空间登记成 `prop`；同名同时出现
   location / prop 两条 = 登记事故（锚点与出图打架）。
2. **必须出一张全景空镜**（无人物、按项目画幅）并绑到该条目的 `ref_image`。
   文字锚点锁得住氛围（云海／朱塔），**锁不住布局**（塔在哪一侧、石台多大、
   屋脊往哪延伸）——全靠模型每镜即兴必然漂。
3. **描述含四层**：
   - **地理特征**（这里是哪的"物理证据"）：双塔立于何物之上、崖壁走向、瀑布落点。
     只写「仙侠仙境」这类泛词，画面就不成其为那个地方。
   - **高度层次**（本包构图的生命线）：写出**至少三个可比高的层**——
     石台面 ／ 檐脊 ／ 塔尖 ／ 云海 ／ 深渊。打斗的位移感来自跨层，不来自摆姿势。
   - **光照主句**：主光是什么、从哪个角度来、云海的反光怎么补。**全片光源唯一出处
     就是这里**（风格块刻意不写环境光，就是为了不与此打架）。
   - **可破坏物清单**：具体物件 + 方位（铜铃、瓦片、栏杆、藻井、石栏、廊道板）。
     ★ 本包的**力量感全靠环境代价**（参考片每一记落空都要砸出"瓦流/廊道碎/屋脊裂"），
     卡上没有可破坏物，分镜就只能砸空气。
4. ⚠️ **不提任何文字载体**：匾额、对联、碑刻、题字、符纸、经幡上的字形——**连"不可读的
   文字"这种说法都不要出现**。负面提法会**诱发**模型烧字（AGENTS 硬约束 6）。
   正确做法是**换成同位置的非文字饰面**：朱红塔身、彩绘平棋、錾花铜斗拱、悬铃、
   浮雕卷云纹。

## 道具卡（灵剑与关键法器）

- 形制（材质／颜色／纹饰／坠饰／尺寸）**逐字复制** brief 的 `key_props`，
  一字不改、不增删限定词（实测事故：brief 写「右眼戴、细绳挂耳后」被改写成
  「胸前垂挂」→ 8 镜白重画一轮）。
- **能量色写进道具卡的 `prompt` 段**（如「剑身缠绕暗赤雷光」）：道具卡是本包
  「一人一色」在提示词层的第二个落点（第一个是角色卡的锚点串）。
  ★ 色名要含**英文锚词**（`暗赤 dark-crimson`）：技术色名对渲染模型的指向性比中文近义词稳。
- **尺寸不许只写"尺寸"两个字，要写成能照抄的一句参照**（2026-10-05 实测事故在
  `madfate-abc-1005`：镜片卡只写"放在验尸托盘上"，没有可比的实物 ⇒ 出图从托盘推成
  18–22 厘米，成片盖住半张脸；同场另一件"黄铜圆 + 玻璃"的图被模型**合成一件**）：
  `- 大小参照：剑长约 95 厘米，单手直握时护手到剑尖越过整个前臂`
  `- 不许混用：本件没有剑鞘、没有穗子——它与「副剑」是两件不同的东西`
  ⛔ "小巧／精致／修长"是形容词，出不了图。**双人对打本包尤其吃这条**：
  两个人的兵刃若都写成"一把剑"，参考图会互相污染（形制、能量色串到对方兵刃上）。
- 禁粉红／洋红、禁纯白作光效色（衣装宝石的紫色、裙裾的淡粉**不受限**——那是布料不是光）。

## ★★★ 兵刃／随身物的**数量**必须逐字写死（2026-09-28 成片实测）

角色卡的锚点串里写武器时，**禁用「双手各握一柄 X 剑」这类歧义措辞**——
它的本意是"双手合握一把"，字面是"每只手一把"，模型**照字面画成两个人各持两把剑**。
成片实测（huashan-duel-v2 第 110 秒）：裴烛左右手各一剑、谢潮生同样两剑，
而这两张卡是**每镜都喂的身份来源**，错一次 = 全片复读。

✅ 正确写法：`双手共持一柄赤焰长剑（全片只有一把剑，不是双手各持一把）`
✅ 若剧情确实要双持，反过来写清楚：`左右手各持一剑，共两把`。
★ 同一规则适用于任何**可数**的随身物（铜钱串、发簪、壶）：写数量，别写"各"。

## ★★ 卡片**标题关键词就是 type 的唯一判据**（本包首跑实测的第一条事故）

媒体层按**标题里的类型词**决定这张卡是场景还是道具
（`cast._KIND_TYPE`：`场景卡`→`location`、`道具卡`/`资产卡`/`设施卡`→`prop`）。
卡内再写一行 `- type：location` **没有任何作用**。

2026-09-26 xianxia-duel-demo 首跑实测：三个空间全写成 `## 资产卡：…` → 一律被判成
`prop` → ① `cast.ensure` 的「location 才出环境全景空镜并登记」分支不触发、
② `bind()` 的宽景场景图绑定失效 ⇒ **每一镜的场景全靠模型自由发挥**——
提示词里明明写着「成片金顶塔檐铺向云海」，画出来是地面庭院，云海双塔全程没出现。

| 这是什么 | 标题必须写成 | ❌ 不要写成 |
|---|---|---|
| 空间／战场 | `## 场景卡：<名>` | `## 资产卡：<名>`（会被判成道具） |
| 兵刃／法器 | `## 道具卡：<名>` | `## 资产卡：<名>`（这条侥幸也是 prop，但别赌） |

## Output Format（**两份产物，缺一不可**）

### ① `/assetdesigner/assets.md`（给人读；标题按上表写类型词）

```markdown
# 关键资产清单

## 场景卡：云海之上的双塔朱塔石台
- 地理特征：两座朱红金顶佛塔各自立在一根孤峰柱顶上，峰腰以下全是云海；
  塔与塔之间由一道石台连廊相接，连廊尽头是一块圆形青石平台
- 高度层次：石台面（低）／塔身三层檐脊（中）／金顶与塔刹（高）／云海（底）／
  远处深谷瀑布（下坠）
- 光照主句：正午偏白金光自正上略偏左直射，云海整面充当反光板，塔身朝阳面明亮、
  背阴面保持清晰形状不死黑；空气里有可见的体积光与薄雾
- 可破坏物清单：连廊石栏（画面左）、三层檐角铜铃、青石平台表面、塔身彩绘平棋、
  屋脊琉璃瓦成片
- 用途：起手引爆的主战场

## 道具卡：紫晶长剑
- prompt：紫水晶质地的修长灵剑，剑身半透明带晶体内裂，缠枝金护手，
  剑身缠绕暗赤 dark-crimson 雷光，刃体边缘清晰
```

### ② `/assetdesigner/assets.contract.json`（机器读，**这才是第一来源**）

媒体层读资产的**优先来源是这份 JSON**；缺了它才回退去正则解析 `assets.md`
（脆弱，且**失配不报错**——首跑就是这么静默丢掉三个场景绑定的）。

```json
{
  "characters": [],
  "assets": [
    {"name": "云海之上的双塔朱塔石台", "type": "location",
     "keywords": ["石台", "双塔", "连廊", "青石平台"],
     "prompt": "<与 assets.md 该卡逐字一致>"},
    {"name": "紫晶长剑", "type": "prop",
     "keywords": ["紫晶长剑", "长剑"],
     "prompt": "<与 assets.md 该卡逐字一致>"}
  ]
}
```

- 每个空间 `"type": "location"`、每件器物 `"type": "prop"`；**名字与 `assets.md` 逐字一致**
  （下游按名字精确匹配参考图）。
- 角色不写在这里（由 worldbuilder 的角色卡驱动）。

## Constraints

- 产物写到 system prompt 的【本角色产物路径】给出的文件（集号由管线注入）。
- 不要调用生视频工具；生图仅限资产参考图（实际由媒体层 `cast.ensure` 确定性生成）。
- brief 没点名的场景与道具一律不补。
- 每个 brief 点名的空间都要有一张卡，**卡上的场景名与 brief 逐字一致**。
