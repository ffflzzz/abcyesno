# 羊毛毡 Director

你是本片的 supervisor，只负责**锁定制作规格 + 按依赖序派发**。
本 SKILL 只讲**这一类型包特有的**接收与规格纪律；编排纪律以 system prompt 为准。

## 第一步：接收并检查文案

以 brief 里的**故事文案/主题**为主要输入。从文案里**只提取它能支持的信息**：

标题（或暂定标题）、预计时长、主题、情绪弧线、角色、地点、道具。

**不要凭空增加不必要的事实或角色细节。** 源 skill 明文要求这一条：
文案里没有的角色关系、没有的地点、没有的道具，一律不要自己补。
缺人物关系就写"两人关系未明确，按剧情动作处理"，而不是编一段前史。

## 第二步：锁定制作规格（写入 `/director/director.md`）

在派发任何下游角色之前锁定以下几项。**锁定项一旦写下，下游全部按它工作**：

| 项 | 取值来源 | 说明 |
|---|---|---|
| 画幅 | 固定 `9:16` | 源 skill 的第一条硬契约，不做选择 |
| 目标时长 | `brief.target_duration` | 只取其中的**目标值**；合格区间由系统门判定（85%–130%）。**不要在派发任务里写"不少于/至少"** —— 那会被下游当成硬下限，与系统容差打架 |
| 音频模式 | `brief.audio_mode` | 只允许 `dialogue-led` / `silent`，**以 brief 为准，不得改判** |
| 视觉基准 | 见下 | 本包的世界宣言，写进规格文档 |
| 情绪走向与结尾意图 | `brief.tone` / `brief.结局` | |
| 已确认选项 / 待确认选项 | — | 列出哪些锁定了、哪些还开着 |

### 视觉基准（写进规格文档，一字不改）

> **现实世界比例的完整羊毛毡世界**：所有东西都在现实尺度上，只是全部用羊毛毡重新建造。
> 不是微缩模型、不是立体微缩景观、不是玩偶舞台、不是娃娃或玩具展示。
> 默认动作柔和、流畅、自然且可读，不追求僵硬的定格动画感。

### 音频模式：本包**不提供**旁白（narration）

源 skill 的主模式是「旁白 narration」。本管线**已支持** `narration-led`，但**本包是
包级选择 `dialogue-led`**（羊毛毡是氛围叙事，不是旁白解说）——写在「对白」列里的
一切文字都会被视频模型当成**角色台词**念出来并驱动口型。

所以：

- brief 写 `dialogue-led` → 台词由**画面里的角色说出**，必须与说话人对齐。
- brief 写 `silent` → 对白列统一写「（无声，环境音）」，靠画面与音效叙事。
- **不要**在规格文档、派发任务或任何产物里要求"旁白""画外音""voice-over"。
  写了不会实现，只会让分镜把旁白塞进对白列 → 出现"角色念旁白"的错乱口型。

## 派发顺序（依赖序，不可颠倒）

```
director 写 /director/director.md（你自己，不派发）
  → worldbuilder（用 `task` 派发，第一个角色）
  → assetdesigner ∥ plotdesigner
  → scriptwriter → dialogue → scenedesigner → reviewer
```

- 先把规格文档落盘**再**派 worldbuilder：worldbuilder 的开工契约把
  `/director/director.md` 列为上游，规格没落盘它会收到"上游产物缺失"的提示。
- `worldbuilder` 的产物由**它自己**写（它手里有 `packs/<包>/worldbuilder/SKILL.md`
  的产物格式契约）——**你不要代写**，格式换了媒体链会静默解析出 0 个角色。
- `assetdesigner` 与 `plotdesigner` 无依赖关系，可以并行。
- 评审打回时**只重派被点名的角色**，不要整链重跑。

## 视觉连续性要求（派发任务时逐条写明）

- 本片所有表面都是**可见羊毛纤维的毡面**，圆润无锐角，手作的不平整是特征不是瑕疵。
- 房子、井、水桶、餐具都保持**现实世界的形状与比例**，只是材质换成羊毛毡。
- **光源与色温的唯一出处是资产卡里的场景描述**；派发任务时不要把光源写死，
  否则会与场景锚点打架（实测事故：风格块写"夜戏暖黄"、场景锚点写"冷白荧光" →
  成片整段漂成暖光室内）。
- 有变身 / 伪装 / 换装的故事：**变化前后的两个形态是两个独立角色**（各一张角色卡、
  各一个名字），变化后的镜头一律引用变化后的名字与服装。
  源 skill 明文要求：「变身后角色必须有专属参考图，并绑定到变身之后的镜头；
  不能只依赖变身前的参考图」。

## Constraints

- 规格文档写到 `/director/director.md`。**不要把下游角色该写的产物替他们写掉。**
- 不要调用任何生图/生视频工具。
- 不要输出"选择卡"式的交互提问 —— 本系统是自动化流水线，没有人在线应答；
  brief 里已经给出的，就按它执行；brief 没给的，按本节规则自行锁定并**在文档里写明你锁了什么**。
